# ICP 正式分析紀錄整合 — 2026-10-22

## 行為與範圍

- 數據頁頁首「儲存分析紀錄」位於 PDF 匯出左側；一次送出本工作全部採用的金屬／波長及其批次，狀態 UNDER_REVIEW。
- 一份 ICP work_key 對應一筆 AnalysisRecord；不依 PDF 檔名合併不同工作。
- 不建立新資料表、不修改 models.py、不執行初始化／Migration；source_type 使用 ICP_IMPORT。
- AnalysisWorkState 保存 ICP_RECORD_V1 完整快照：原始解析、候選選擇、LIMS 配對及採用決定、各金屬／波長／批次設定、檢量線、RSD(n=3)、樣品計算及排除資料、QA/QC、PFM 與各版本設定。
- 正式快照中的顯示結果與 PDF 使用儲存時計算內容；Excel 另外凍結每個金屬／波長的 LIMS 匯出值。歷史匯出不重新查詢 LIMS、CSV 或重新計算結果。
- Excel 仍限定同批次同檢測代碼一個波長；未配對但採用的原樣可作為 QA/QC 原樣，不建立不存在的 LIMS 委測。
- 送出前重新確認工作 token、設定／配對 token、官方 ACTIVE PFM 管制及 QA/QC 可判定性。既有超出管制結果會如實保留，不改為合格。
- 本頁未暫存修改會提示先暫存；其他金屬已儲存的資料來自同一工作 JSON。尚無法完成設定／檢量線／QA/QC 的採用項目，會阻止整批送審。

## 交易與生命週期

- 呼叫端擁有 transaction；工作 JSON CAS、正式紀錄、完整快照、PFM 關聯共同 Commit 或 Rollback。
- 已送審工作保留資料、標示 SUBMITTED，於暫存清單 SQL 篩除；不實體刪除原始工作。清單不讀取全部工作的大型 PDF JSON。
- 重複送出或舊工作 token 拒絕，不重複新增；舊 ICP 表單 POST 不得修改送審工作。
- 新匯入工作記錄建立者。舊未標示建立者的暫存維持相容，在首次正式送出時確立原分析員；不宣稱已驗收所有既有 ICP 暫存的跨帳號隔離。
- 正式明細以金屬／波長切換，顯示各批次完整檢量線、樣品、QA/QC 及共用 PFM，維持既有審核作業。
- 退回後可由原分析員或具審核權限者進入修正；保留原分析員身分，記錄 RESUME_ICP／RESUBMIT 操作者。
- 修正中工作指定目前編輯者；重開不以舊快照覆蓋已修改值。重新送審更新原 analysis_id。
- 若已有其他未完成 ICP 工作，進入修正提示衝突，不覆寫目前工作。
- 混合類別主檔 category=MULTI；類別查詢及 PFM 歷程由快照類別索引匹配 G／W。金屬標籤、中文檢測名稱亦納入查詢。
- 刪除正式紀錄沿用權限、原因與稽核；工作標示 DELETED 並隱藏，不恢復成孤兒暫存。ICP 手動 PFM 事件獨立存在，刪除正式紀錄僅清除其關聯，保留量測歷程。

## 隔離驗證

- 使用實際 ICP5800 PDF、方法／年度管制 CSV 與原 LIMS Excel 範本；LIMS 配對採模擬資料。
- Cd＋Zn、每金屬三個批次：一筆正式紀錄、六個批次結果、完整原始 JSON 與一筆 PFM 關聯。
- 儲存完成但外層 Rollback：正式紀錄、快照、關聯與工作狀態均還原。
- 成功提交、重複與舊版本拒絕、暫存清單隱藏／修正時恢復、審核者修正後更新原紀錄及保留原分析員。
- 正式 Excel 使用凍結數值，產出六筆品管及 56 筆分析結果，不依賴即時 CSV／LIMS／計算服務。
- 混合 G／W 類別查詢及 PFM 歷程、明細與金屬切換、既有單項明細分支、HTTP CSRF／工作／設定版本限制、舊表單鎖定。
- 刪除正式紀錄的稽核、工作隱藏與 PFM 事件保留。
- Python 3.8 語法、JavaScript 語法、精確來源檢查、唯讀預檢、備份安裝、重複安裝與異版拒絕。

## 尚待使用者環境驗收

- Flask 實際瀏覽器儲存、查詢、審核、退回修正及再次送審。
- 真實 LIMS 委測資料的匯出／匯入，以及實際多帳號並行操作。
- Server Firebird 部署與執行環境另行驗收；本修正包不連線或操作 Server 資料庫。
